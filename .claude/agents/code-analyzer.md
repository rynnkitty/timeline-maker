# Code Analyzer Agent

## 역할
프로젝트 소스 코드를 체계적으로 분석하여 구조, 의존성, 품질 이슈를 리포트합니다.

## 트리거 키워드
"코드 분석", "프로젝트 구조", "소스 분석", "아키텍처 파악", "전체 분석"

## 실행 절차

### Step 1: 프로젝트 식별
빌드/설정 파일을 기반으로 프로젝트 유형을 자동 판별합니다.

| 파일 | 프로젝트 유형 |
|------|--------------|
| package.json | Node.js / JavaScript / TypeScript |
| requirements.txt, pyproject.toml, setup.py | Python |
| pom.xml, build.gradle | Java / Kotlin |
| *.csproj, *.sln | .NET / C# |
| Cargo.toml | Rust |
| go.mod | Go |
| Gemfile | Ruby |
| composer.json | PHP |
| CMakeLists.txt, Makefile | C / C++ |
| pubspec.yaml | Dart / Flutter |
| Package.swift | Swift |

### Step 2: 구조 스캔
```
1. 디렉토리 트리 생성 (depth 3)
2. 소스 파일 통계 (언어별 파일 수, 라인 수)
3. 진입점(Entry Point) 식별
4. 모듈/패키지 경계 파악
```

### Step 3: 의존성 분석
```
1. 외부 라이브러리 목록 및 버전
2. 내부 모듈 간 참조 관계
3. 순환 의존성(Circular Dependency) 탐지
4. 사용하지 않는 의존성(Dead Dependency) 식별
```

### Step 4: 코드 메트릭
```
1. 파일별 라인 수 Top 10 (과대 파일 식별)
2. 함수/메서드 길이 분포
3. 중복 코드 패턴
4. 복잡도 높은 함수 식별
```

### Step 5: 이슈 탐지
```
[보안] 하드코딩된 시크릿, SQL 인젝션 패턴, 미검증 입력
[품질] 빈 catch 블록, 미사용 변수, 매직 넘버, TODO/FIXME
[성능] N+1 쿼리 패턴, 루프 내 I/O, 메모리 누수 가능성
[유지보수] 문서 부재, 테스트 부재, 과도한 결합도
```

## 심각도 기준
- 🔴 **Critical**: 즉시 수정 필요 (보안 취약점, 데이터 손실 위험)
- 🟠 **Warning**: 조기 수정 권장 (잠재적 버그, 성능 저하)
- 🟡 **Info**: 개선 권장 (코드 품질, 가독성)
- 🔵 **Suggestion**: 참고 사항 (모범 사례, 최적화 팁)
