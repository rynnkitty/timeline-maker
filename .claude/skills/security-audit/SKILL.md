# Security Audit Skill

## 목적
프로젝트 코드에서 일반적인 보안 취약점을 탐지하고 수정 방안을 제시합니다.

## 점검 항목

### 1. 시크릿 노출
```
탐지 대상:
- 하드코딩된 API 키, 비밀번호, 토큰
- .env 파일이 .gitignore에 없는 경우
- 설정 파일 내 평문 자격 증명
- 소스 코드 내 connection string

검색 패턴:
  password, secret, api_key, token, credential
  "-----BEGIN.*KEY-----"
  base64로 인코딩된 자격 증명
```

### 2. 인젝션 공격
```
SQL Injection:
  - 문자열 연결로 쿼리 구성
  - 파라미터 바인딩 미사용
  - ORM raw query 사용 시 미검증 입력

XSS (Cross-Site Scripting):
  - 사용자 입력의 미이스케이프 출력
  - innerHTML / dangerouslySetInnerHTML 사용
  - 템플릿 엔진의 raw 출력

Command Injection:
  - exec(), system(), eval() 에 사용자 입력 전달
  - 파일 경로에 사용자 입력 포함
```

### 3. 인증/인가
```
- 인증 우회 가능 경로 존재
- 권한 검사 누락된 엔드포인트
- 세션/토큰 만료 미처리
- CORS 설정 과도하게 허용 (*)
```

### 4. 데이터 보호
```
- 개인정보 평문 저장
- 로그에 민감 정보 출력
- 에러 메시지에 내부 정보 노출
- 암호화 알고리즘 취약 (MD5, SHA1 등)
```

### 5. 의존성 보안
```
- 알려진 취약점이 있는 패키지 버전
- 불필요한 의존성 (공격 표면 증가)
- 미신뢰 소스의 패키지
```

## 심각도 분류

| 등급 | 설명 | 조치 기한 |
|------|------|-----------|
| 🔴 Critical | 즉시 악용 가능, 데이터 유출 위험 | 즉시 |
| 🟠 High | 특정 조건에서 악용 가능 | 1주 이내 |
| 🟡 Medium | 간접적 위험, 방어 계층 존재 | 1개월 이내 |
| 🔵 Low | 모범 사례 미준수 수준 | 다음 릴리스 |

## 출력 형식

```markdown
# 🔒 보안 점검 리포트

## 요약
- Critical: N건
- High: N건
- Medium: N건
- Low: N건

## 발견 사항

### 🔴 [Critical] 이슈명
- **위치**: 파일:라인
- **설명**: 취약점 상세
- **위험**: 공격 시나리오
- **수정**: 구체적 수정 방법 + 코드 예시
```
