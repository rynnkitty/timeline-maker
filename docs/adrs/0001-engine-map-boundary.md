# ADR 0001 — 엔진·지도 경계, 진행 축, 카메라 모델

- 상태: 채택 (2026-09-23, Phase 3 · D-23 위임, 권고안)
- 관련: D-19 · D-24 ~ D-30 (`CLAUDE.md` §3), `docs/phase3-lookfeel.md`, `docs/spike-results.md` §3

## 맥락

미리보기와 내보내기는 같은 `renderFrame(t)` 를 써야 하고(H-6), 엔진 계산은 DOM·MapLibre 없이 테스트돼야 한다(에이전트 §4). 트레일은 지도 위에 정확히 겹쳐야 하므로 두 계층의 투영이 같아야 한다.

## 결정

1. **투영은 엔진이 소유한다.** `src/engine/mercator.ts` 가 512px 월드 Web Mercator 를 직접 계산하고, 카메라는 `{x, y(단위 메르카토르), zoom(출력 폭 480 기준)}`. 지도 계층(`src/map/`)은 엔진의 `MapRenderer` 인터페이스(`render(camera, frame) → 이미지`)를 구현하며, 카메라를 MapLibre `jumpTo` 로 번역한다. 엔진은 MapLibre 를 import 하지 않는다 (지도 → 엔진 타입 의존, 역방향 없음).
   - 정합 검증: `map.project` 대비 최대 0.42 px (480) · 0.17 px (1080).
   - 라벨 배율 k: 컨테이너 480/k CSS px + pixelRatio W/(480/k) + MapLibre 줌 −log2 k. k 는 정수 컨테이너 폭에서 역산.
2. **진행 축 = 누적 거리 (D-24).** `Timeline` 은 시간이 아니라 진행량(pace: km, 이동 0 이면 점 순번)을 프레임에 선형 배분한다. 트레일 나이·카메라 창도 pace 기준 영상초.
3. **카메라 = 평활된 창 bbox + 헤드 (D-25).** 프레임별 원시 창 bbox(과거 1.5 s · 선행 0.5 s)를 삼각형 커널(K=12)로 평활한 뒤 헤드를 부드럽게 합치고(soft max) fit. 줌 상한 9 와 폭/높이 제약 전환도 부드러운 함수. 시작 이전 창 = 첫 점 중앙·z7.7 가상 박스. 전 프레임 사전 계산 → 임의 접근 = 순차 계산.
4. **지도 결정론은 시간 제거로.** `setNow` 대신 `fadeDuration: 0` + 스타일 `transition: 0` (시간 고정 시 초기 전환이 끝나지 않아 `idle` 이 오지 않을 위험). 캡처 = `preserveDrawingBuffer` + `once('idle')` 선등록 + `triggerRepaint`.

## 결과

- 장점: 엔진 전체가 Node 에서 테스트됨(64개), 제공자 교체가 설정 한 곳, 투영 불일치 버그 없음.
- 대가: 지도 출력은 카메라 이력에 의존(C-8) — 내보내기는 새 인스턴스·프레임 0 부터 순차, 미리보기는 인스턴스 재사용으로 스크럽 시 라벨 배치가 미세하게 다를 수 있음(D-28).
- 거리 선형은 이동 없는 기간을 빠르게 지나간다 — 레퍼런스와 같은 동작이다. 다만 D-05 문구와 다르므로 사용자 확인이 권장된다.
